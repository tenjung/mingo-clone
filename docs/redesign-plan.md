# 얼씨구 다현 개편 계획과 결과

작성일: 2026-10-16 (한국 시간)

## 문제와 원인

기존 저장소의 마지막 커밋은 `c502f7e`. 저장소를 현재 폴더에 clone한 뒤 `codex/fan-cafe-redesign` 브랜치에서 작업했다. 원본은 Git 이력에 보존되어 있다.

기존 메인은 일반 홍보 사이트의 큰 캐러셀과 카드 중심이었다. 좌측 게시판 메뉴가 없고 헤더 메뉴는 라우트로 연결되지 않았으며, 김다현의 실제 활동으로 확인되지 않은 앨범·공연 공지가 정적 배열로 들어 있었다. 기존 글쓰기는 새 글 insert 대신 라우트 ID에 update를 수행했고 새 글 생성 진입점이 제대로 연결되어 있지 않았다. Zustand에 저장한 사용자 표시 상태와 실제 Supabase 세션이 따로 관리되었다.

해결 목표는 화려한 홍보보다 ‘방문 → 공지 확인 → 게시판 읽기 → 로그인 → 글쓰기’ 흐름을 짧게 만드는 것이다. 사용자가 가수 김다현을 대상으로 확정했으므로 기존 ‘얼씨구 다현’ 이름을 유지했다.

## 구현 순서와 완료 사항

1. Git 이력을 보존한 채 로컬 clone과 작업 브랜치 생성.
2. 카페 대문, 좌측 메뉴와 회원 영역, 우측 공지·게시글·사진첩 구성.
3. 공식 팬카페에서 추출한 핑크·흰색, 얇은 구분선, 작은 모서리, 고딕 본문과 대문용 명조체 적용. 모바일에서 메뉴를 접도록 변경. 최초 브라우저 확인 후 보조 글씨 크기와 대비를 높임.
4. App Router 서버 페이지와 Server Actions로 전환. 기존 topics 계약 유지, 로그인 세션을 쿠키로 통일.
5. 새 글 insert, 서버 사용자 확인, 카테고리 검증, 5MB 사진 제한, 실패 시 입력 유지, 본인 글 삭제와 명시적 삭제 확인 구현.
6. 공지·게시판·사진첩·검색·달력·안내·인증 화면을 실제 라우트에 연결. 임의 일정·회원 수·인기 수치 삭제.
7. 빌드·타입·회귀 테스트와 데스크톱·모바일 브라우저 점검.

## 지연 원인과 변경

원격 Supabase 호스트의 DNS 조회 실패가 먼저 확인되었다. 설치된 PostgREST 클라이언트의 GET 요청 자동 재시도가 1·2·4초 backoff를 사용하여 연결 실패 화면까지 약 7.6초가 걸렸다. 클라이언트 설정 `db.retry: false`로 자동 재시도를 없애고 명시적 다시 불러오기 버튼을 연결했다. 데이터를 성공처럼 위장하거나 빈 게시판으로 처리하지 않는다.

개발 서버에서 변경 후 측정한 HTTP 전체 응답 시간은 홈 약 0.17초, 자유게시판 약 0.70초였다. 이는 동일 로컬 환경에서 **원격 DNS 연결 실패 상태**를 확인한 표본이며, 정상 DB의 성능이나 운영 환경의 지연 보장은 아니다.

## 검증 범위

- 프로덕션 빌드 및 TypeScript 검사
- 회귀 테스트: 로그인 복귀 주소의 외부 이동 방지, 원본 BlockNote 본문/중첩 링크 텍스트, 잘못된 JSON의 텍스트 처리, 새 글 직렬화 계약, 일반 회원의 공지 작성 제외
- 브라우저: 메인 렌더링과 사진 표시, 상단·좌측 메뉴, 게시판 검색어 유지, 비회원 글쓰기 → 로그인 연결
- 달력: 한국 시간 기준 현재 월, 다음 월 이동
- 모바일: 390px 화면에서 가로 넘침 없음, 접이식 메뉴 열림, 사진 정상 로딩
- 의존성 검사: npm audit 0 vulnerabilities (설치 시 감지된 source-map-js 취약 버전은 lockfile에서 패치 버전으로 갱신)

실제 DB 스키마·RLS와 실제 인증·쓰기 성공은 DNS 연결 실패로 검증하지 못했다. 달력은 날짜 탐색 화면까지 구현했으며, 일정 데이터와 관리자 등록은 포함하지 않았다. 배포·원격 push·원격 DB 변경은 수행하지 않았다.

## 포인트 컬러 변경 (2026-10-16)

사용자 요청에 따라 녹색 테마를 제거하고 [공식 다음 팬카페의 공개 스타일시트](https://cafe.daum.net/_c21_/css/1YpG2/322/20261001140913.4/20260401183951.27/20261001140913.2.css?grpid=1YpG2)에서 실제 사용하는 `#F361A6`를 기준색으로 적용했다. 해당 원문에서 `.menuList .group_tit`, `.txt_point`, `.txt_point_bg`에 같은 색이 지정되어 있다. 응원색의 공식 HEX를 별도로 단정한 것이 아니라, 현재 팬카페 화면에서 추출한 색이다.

- 기준 핑크 `#F361A6`, 버튼 호버 `#EE529E`, 진한 핑크 `#B82366`, 연분홍 `#FFF1F7`.
- 버튼 글씨는 `#261A22`: 기본 상태 대비 5.64:1, 호버 상태 5.06:1. 흰색 작은 글씨는 사용하지 않는다.
- 선택 메뉴는 진한 핑크 글씨와 연분홍 배경: 대비 5.53:1. 기능 아이콘·포커스도 진한 핑크로 표시한다.
- CSS의 녹색 변수와 테마 하드코딩을 의미별 토큰으로 정리하고 대문 SVG와 파비콘도 같은 팔레트로 변경했다. 성공·오류·삭제의 의미를 나타내는 상태색은 유지했다.
- CSS의 배치·글씨 크기 선언과 SVG 도형은 변경 전과 동일함을 비교 확인했다. API·DB·의존성 변경은 없다.

## 찐팬카페 명칭과 실용 메뉴 개편 (2026-10-16)

사용자가 최종 지정한 이름은 **트롯 요정 김다현 찐팬카페**다. 대문에는 ‘트롯 요정’과 ‘김다현 찐팬카페’를 나눠 표시하고 문서 제목·접근성 이름은 전체 이름을 사용한다. 상단·사이드바·안내·로그인·푸터는 공통 설정의 짧은 이름과 ‘김다현 찐팬 커뮤니티’ 표현을 사용한다. ‘얼씨구다현’은 외부 참고 카페를 지칭할 때만 사용한다.

공식 카페의 공개 홈에서 실제로 제공하는 메뉴 응답(`bbs_menu_ajax`)을 읽어 스케줄 게시·캘린더, 공연 상세 공지, 방송 후기, 투표·스밍, 가입·이용 질문, 사진·영상을 확인했다. 이를 안내 / 소식·일정 / 함께하는 찐팬 / 사진·영상 네 묶음으로 압축했다. 소규모 자발적 커뮤니티에 운영 체계가 없는 후원·회계·버스·굿즈 신청과 아티스트 본인 전용 게시판은 도입하지 않았다.

일정은 공연·행사와 방송 필터, 달력·목록 보기, 제보 진입점, 공식 원문 링크를 제공한다. 월 이동과 보기 방식 변경 시 유형 필터를 유지한다. `src/data/schedules.ts` → Repository → 홈 요약과 일정 화면이 같은 자료를 사용한다. 원문 본문은 403 응답으로 확인하지 못했으므로 등록 일정은 현재 비어 있다. 제목만 보고 공연 시간·장소를 추정하지 않았다. 신규 DB 테이블·유료 API·주기적 스크래핑 없이 시작하며, 원문 확인 후 자료 파일에 반영하는 방식이다.

신규 게시판 ID `question`, `news`, `schedule-tip`, `cheer`는 메뉴·쓰기 선택·서버 허용 목록에 공통 도메인 정의로 연결했다. 기존 ID와 게시글은 변경하지 않았다. 회귀 테스트에 날짜·유형 필터, 한국 시간, 윤년·연도 경계, 메뉴와 쓰기 계약 일치를 추가했다.
